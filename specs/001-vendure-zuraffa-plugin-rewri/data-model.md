# Data Model — Rewrite Vendure Flutter SDK with Zuraffa v5 + Zorphy

**Phase 1 output** · generated 2026-08-06 · target: `lib/src/domain/entities/`

This document defines the entity inventory and the mechanical mapping rules from
the current Freezed trees to the new Zorphy-style entities. The **public symbol
surface is the invariant**: every symbol exported today by
`lib/src/types/exports.dart` (211) and `lib/src/input_types/exports.dart` (213)
must remain importable, with the same name and field shape, from the new
locations.

Response entities (from `types/`) keep non-nullable fields where the Freezed
factory declared `required`; input entities (from `input_types/`) keep
all-nullable fields. Field names, types, defaults and `@JsonKey` renames are
copied verbatim.

## 2. Entity classes: two forms

### 2.1 Fallback form (default) — concrete `@JsonSerializable` class

Used for every entity that references another entity (cross-file import) — i.e.
the overwhelming majority (zuraffa #272 blocks their `.zorphy.dart`).

```dart
// Auto-generated by the entity migrator (FR-003 fallback, flagged in PR)
import 'package:json_annotation/json_annotation.dart';
import '../country/country.dart';
import '../enums/index.dart';

part 'address.g.dart';

/// Address entity (response form)
@JsonSerializable(explicitToJson: true)
class Address {
  const Address({
    required this.id,
    required this.country,
    this.customFields,
    this.streetLine1,
    ...
  });

  factory Address.fromJson(Map<String, dynamic> json) => _$AddressFromJson(json);

  final String id;
  final Country country;
  final Map<String, dynamic>? customFields;
  final String? streetLine1;
  ...

  Map<String, dynamic> toJson() => _$AddressToJson(this);
}
```

Rules:
- **Fields**: identical names/types/defaults to the source Freezed class.
- **`@JsonKey`**: preserved verbatim (`name: '_and'`, `name: '_or'`, enum
  aliases, `defaultValue`, converters).
- **Custom fields** stay `Map<String, dynamic>?` (dynamic — VendureUtils already
  fills nulls via `c<T>`).
- **No `copyWith`, no `==`/`hashCode`, no `when()` extensions** — not used by
  the test suite (research R2); dropping them is listed as a breaking change
  (AC-7).
- The migrator emits these mechanically from the Freezed source (plan Phase 1,
  step 6); unions and enums are hand-crafted (steps 7–8).

### 2.2 Generated form — `@Zorphy` abstract class + both part files

Used for scalar-only leaf entities (fields are only primitives/String/DateTime/
enums — no entity-typed fields), e.g. `Coordinate`, `CoordinateInput`,
`GlobalFlag`-style enums aside. This is the FR-003 generation exercise.

```dart
// Generated via `zfa entity create Coordinate` (generator works: no cross-refs)
import 'package:zorphy_annotation/zorphy_annotation.dart';

part 'coordinate.zorphy.dart';
part 'coordinate.g.dart';

/// Coordinate entity
@Zorphy(generateJson: true, generateCompareTo: true)
abstract class $Coordinate {
  double get x;
  double get y;
}
```

The zorphy builder emits the concrete class; json_serializable emits `.g.dart`.
**Invariant**: the resulting concrete class exposes the same
`fromJson`/`toJson`/field surface as the fallback form so consumers cannot tell
the two forms apart.

## 3. Union/sealed result types (19 per tree)

Hand-crafted. The critical contract (from the current Freezed design):

- `fromJson` dispatches on the **`runtimeType` JSON key** (set by
  `VendureUtils.normalizeGraphQLData`, which rewrites `__typename` →
  lowercased-first-letter key before `fromJson`).
- Each variant is a **distinct concrete runtime class** (so
  `isA<CouponCodeInvalidError>()` resolves).
- `toJson()` serializes the variant's payload **transparently** — the union
  wrapper must NOT add a wrapping key — so
  `Order.fromJson(result.toJson())` re-parses the payload as `Order`
  (~35 test call sites rely on this).
- Variant classes keep their exact field sets from the current sources
  (`ActiveOrderResult.order` carries 30+ fields; `AuthenticationResult` has
  `currentUser` / `invalidCredentialsError` / `notVerifiedError`; etc.).

Representative target shape:

```dart
@JsonSerializable(explicitToJson: true)
sealed class ActiveOrderResult {
  const ActiveOrderResult();
  factory ActiveOrderResult.fromJson(Map<String, dynamic> json) {
    switch (json['runtimeType']) {
      case 'noActiveOrderError': return NoActiveOrderError.fromJson(json);
      case 'order':              return Order.fromJson(json);
      default: throw ...;        // mirrors CheckedFromJsonException behavior
    }
  }
}

class NoActiveOrderError extends ActiveOrderResult {
  const NoActiveOrderError({required this.errorCode, required this.message});
  factory NoActiveOrderError.fromJson(Map<String, dynamic> json) => ...;
  final ErrorCode errorCode;
  final String message;
  ...
}

class Order extends ActiveOrderResult { /* 30+ fields, as today */ }
```

## 4. Enums

One merged enum per name (12 total), based on the `types/` variant (superset;
`ErrorCode` additionally has `unknownError` — value set = union of both trees,
verified at migration time). Serialization stays `$enumDecode`/`$enumDecodeNullable`
via generated `.g.dart` — i.e. string-name-based, matching today's wire format.
Enum-typed entity fields keep their exact type and `@JsonKey(name:)` aliases
(e.g. `CurrencyCode.try_` ↔ `'TRY'`).

## 6. Counts and naming rules

| Source tree | Files to migrate | Target |
|---|---|---|
| `lib/src/types/` (non-generated) | 199 classes (149 `@freezed` + 50 `@unfreezed`) + 12 enums + `exports.dart` | `domain/entities/{snake}/` + `enums/` |
| `lib/src/input_types/` (non-generated) | 199 classes + 12 enums + `paginated_list.dart` + `vendure_query_options.dart` + `exports.dart` | same, flat namespace (names disjoint) |
| Merged enums | 12 pairs → 12 | `enums/` (+ barrel) |

- `{snake}` = lower_snake_case of the class name (`ActiveOrderResult` →
  `active_order_result/active_order_result.dart`).
- The **12 enum names collide** between trees and are merged (one declaration —
  this also removes the duplicate-symbol export ambiguity between the two
  barrels).
- No other name collides (`types/` response names vs `input_types/` names are
  disjoint by construction).
- `PaginatedList<T>` is generic and hand-written (unchanged body) — not a
  Freezed/Zorphy entity.

## 7. Validation rules carried over

- **Required response fields** remain non-nullable (`required` in the Freezed
  factory → `required this.x` in the concrete ctor) — tests read
  `order.code`, `products.items.first.id` etc. without null-forgiveness.
- **`include_if_null: false`** stays in build.yaml → `toJson` omits nulls (input
  entities rely on this for clean GraphQL variables).
- **`explicit_to_json: true`** stays → nested entity `toJson()` calls are
  explicit (`instance.country.toJson()`), preserving the wire shape.
- **`any_map: true`** stays → `Map<String, dynamic>` custom fields deserialize
  without converter scaffolding.

## 8. State transitions

Not applicable to entities (stateless DTOs). Order *workflow* state
(`'AddingItems'` → … → `'PaymentAuthorized'` / `'Cancelled'`) remains opaque
`String` values asserted by tests (e.g. `expect(order.state, 'Cancelled')`) —
the rewrite does not introduce an enum for `Order.state`.
